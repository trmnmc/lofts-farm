# Lofts Farm — site

The Lofts Farm economy sim, served as a static site from Cloudflare Workers at
**https://farm.fenley.ai**.

The app is one self-contained file — inline CSS and JS, no external requests,
state kept in `localStorage`.

`src/app.html` is authored as an artifact *body*: it opens at `<meta name="viewport">`
with no doctype, `<html>`, or `<meta charset>`. Served raw, browsers fall into quirks
mode and sniff windows-1252, which mangles em-dashes and `×`. `build.mjs` wraps it in
a real document and writes `public/index.html` (generated, gitignored). `npm run deploy`
and `npm run dev` both build first.

## Layout

    src/app.html        the app (artifact fragment — edit or replace this)
    build.mjs           wraps the fragment into a valid HTML document
    public/index.html   generated by build.mjs — do not edit
    public/_headers     security headers (not served as an asset)
    wrangler.jsonc      Worker + custom domain config

## Prerequisites

- `fenley.ai` must already be a zone in the Cloudflare account you log in as
  (i.e. its nameservers point at Cloudflare). `custom_domain` routes can only be
  created for zones on the same account.

## Deploy

    npm install
    npx wrangler login     # one-time, opens a browser
    npm run deploy

The `custom_domain: true` route in `wrangler.jsonc` makes Cloudflare create and
manage the `farm.fenley.ai` DNS record automatically — nothing to add by hand
in the dashboard. Certificate issuance takes a couple of minutes on first deploy.

Each deploy also publishes to `lofts-farm.<your-subdomain>.workers.dev`.

On Windows PowerShell, the execution policy blocks the `npm`/`npx` `.ps1` shims —
call `npm.cmd` / `npx.cmd` instead.

## Local preview

    npm run dev           # http://localhost:8787

## Updating the app

Replace `src/app.html` and run `npm run deploy` — never edit `public/index.html`,
it is overwritten by the build. Assets are content-hashed and uploaded
incrementally, so redeploys only push what changed.

Note: saved games live in `localStorage` under the site origin. State written by a
build that rendered incorrectly persists across deploys, so after a fix like the
charset one, clear site data or use the in-game Reset to clear stale text.
